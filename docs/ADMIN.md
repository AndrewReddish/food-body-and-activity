# «Тіло» — інструкція для власника

Як люди отримують доступ, як заходять перший раз і далі, і що робити, коли хтось втратив доступ.
Усе адміністрування — у панелі Supabase проєкту `olkchjpqbjhgueftakga`
(https://supabase.com/dashboard → ваш проєкт).

## Два слова, які легко сплутати

| | Що це | Де живе |
|---|---|---|
| **Акаунт** | Email, яким людина входить. Один акаунт = один власник телефона. | Supabase → Authentication → Users |
| **Користувач у застосунку** | Імʼя в списку «Користувачі» (Опції). Кілька людей на **одному** телефоні — кілька користувачів **одного** акаунта. | Таблиця `profiles` |

Наприклад: Олена має акаунт `olena@…`; на її телефоні веде облік і син Макс — це другий користувач того ж акаунта,
окремий акаунт йому не потрібен. Якщо в Макса свій телефон — краще дати йому свій акаунт.

**Паролів немає.** Вхід — кодом або посиланням, які приходять на email. Доступ до акаунта = доступ до цієї пошти.

## 1. Як додати нову людину

### Варіант А — відкрита реєстрація (так налаштовано зараз)
Нічого робити не треба. Надішліть людині посилання на застосунок:
**https://andrewreddish.github.io/food-body-and-activity/** — вона зареєструється сама (крок 2).
Будь-хто з посиланням може створити акаунт; кожен бачить лише свої дані.

### Варіант Б — лише за запрошенням (рекомендовано, якщо коло людей закрите)
1. Supabase → **Authentication → Sign In / Providers** → вимкніть **Allow new users to sign up** → Save.
   Тепер новий email у застосунку отримає помилку «Signups not allowed…», а вже створені акаунти входять як звичайно.
2. Для кожної людини: **Authentication → Users → Add user → Create new user**:
   - Email — її адреса;
   - поставте галочку **Auto Confirm User**;
   - якщо форма вимагає пароль — введіть будь-який довгий випадковий, він ніде не використовується.
3. Надішліть людині посилання на застосунок і скажіть, яким email входити.

> Можна замість «Create new user» натиснути **Send invitation** — людині прийде лист-запрошення.
> Посилання з нього теж працює (його можна вставити в застосунок), але простіше без нього: людина просто входить своїм email.

Хто вже зареєстрований — видно в **Authentication → Users** (email, дата створення, останній вхід).

## 2. Перший вхід (що побачить людина)

1. Відкриває посилання на застосунок в **Safari** на iPhone.
2. **Поділитися → На початковий екран** → «Додати». Далі відкриває застосунок **з іконки** на екрані
   (так він працює як окрема програма й офлайн).
3. Екран **«Вітаємо в «Тілі»»** → вводить email → «Надіслати код».
4. Приходить лист від Supabase (перевірити «Спам», якщо немає за хвилину). Далі одне з двох:
   - у листі є **6-значний код** → ввести його в застосунку → «Увійти»;
   - у листі лише посилання → **утримати посилання → «Скопіювати»** → вставити в поле коду → «Увійти».

   ⚠️ **Не натискати посилання**, якщо застосунок встановлений на екран: воно відкриється в Safari, вхід відбудеться
   там, а не в застосунку, і посилання буде вже використане. Тоді — «Інший email» → надіслати лист ще раз.
5. **«Як вас звати?»** → імʼя → «Продовжити». Готово.

Код і посилання одноразові й діють близько години.

> Щоб у листі був код (зручніше за посилання): Authentication → Emails → шаблон **Magic Link** — додайте
> `<p>Код: <b>{{ .Token }}</b></p>`. `{{ .Token }}` — це змінна, Supabase сам підставить код.

## 3. Наступні входи

- **Входити вдруге не треба.** Сесія зберігається на телефоні й сама подовжується; застосунок просто відкривається.
- Знову попросить email, лише якщо:
  - людина натиснула **Опції → Акаунт → Вийти**;
  - застосунок видалили з екрана або очистили дані Safari;
  - **новий телефон**;
  - iOS очистив дані застосунку, який довго не відкривали.
- Вхід удруге — той самий: email → код/посилання. Імʼя питати не буде, усі дані (раціон, кроки, заміри, фото)
  підтягнуться з акаунта.
- Без інтернету застосунок працює; зміни відправляться, коли зʼявиться мережа.

## 4. Проблеми з доступом

### «Не приходить лист»
1. Перевірити «Спам» / «Промоакції».
2. Зачекати хвилину й надіслати ще раз (частіше ніж раз на ~60 с Supabase не відправляє).
3. Вбудована пошта Supabase надсилає **лише кілька листів на годину на весь проєкт**. Якщо людей багато —
   підключіть свою пошту: Authentication → Emails → **SMTP Settings** (Gmail, Resend, Brevo тощо).
4. Що сталося з листом — видно в **Authentication → Logs** (або Logs → Auth).

### «Забула пароль»
Пароля немає — достатньо доступу до пошти. Людина вводить свій email і отримує новий код.

### Людина втратила доступ до пошти (адресу видалено, забула пароль від пошти)
Переведіть акаунт на нову адресу — дані залишаться:
1. **Переконайтеся, що це справді вона** (дзвінок, особисто): хто отримає нову адресу, отримає всі дані.
2. Supabase → **SQL Editor**, підставте адреси:
   ```sql
   update auth.users
     set email = 'new@example.com', email_confirmed_at = now()
     where email = 'old@example.com';
   update auth.identities
     set identity_data = identity_data || jsonb_build_object('email', 'new@example.com')
     where provider = 'email' and identity_data->>'email' = 'old@example.com';
   ```
3. Людина входить у застосунок з **новою** адресою — все на місці.

### Загубила телефон / хтось чужий має доступ
1. Supabase → Authentication → Users → знайти email → скопіювати **User UID**.
2. **Розлогінити всі пристрої** (SQL Editor):
   ```sql
   delete from auth.sessions where user_id = 'UID-сюди';
   ```
   Сесії на старому телефоні перестануть працювати протягом години (поки не мине поточний токен).
3. Якщо зламано саму пошту — змініть адресу (попередній розділ).
4. Тимчасово заблокувати: у користувача в Authentication → Users → меню **⋯ → Ban user** (зняти — там само).

### Видалити людину і всі її дані
1. Authentication → Users → **⋯ → Delete user**. Записи (дні, заміри, план, користувачі) видаляються разом з акаунтом.
2. Фото лежать окремо — видаліть їх (SQL Editor):
   ```sql
   delete from storage.objects where bucket_id = 'photos' and name like 'UID-сюди/%';
   ```

## 5. Що бачить власник

- Таблиці `days`, `measures`, `plans`, `profiles` у **Table Editor** і фото в **Storage → photos** — вам як власнику
  проєкту видно **все**, у тому числі дані інших людей (застосунок кожному показує лише своє). Не відкривайте
  без потреби й попередьте людей, що адміністратор технічно має доступ.
- Ключ **service_role** / **secret** з Project Settings → API нікому не передавайте й нікуди не вставляйте —
  він обходить усі обмеження. Застосунку потрібен лише publishable-ключ.
- Безкоштовний проєкт Supabase **призупиняється після ~7 днів без запитів**. Застосунок тоді не синхронізується
  (але працює офлайн). Відновити — кнопкою **Restore** на сторінці проєкту.
